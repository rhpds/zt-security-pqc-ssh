= Your Post-Quantum Foundation

Before using post-quantum SSH, let's confirm that post-quantum cryptography is already
enabled on this RHEL 10 system. On RHEL 10.1 and later you do *not* install anything or flip
a preview switch — it is part of the standard configuration.

== Step 1 — Confirm the operating system

[source,bash,role=execute]
----
cat /etc/redhat-release
----

== Step 2 — Look at the system-wide crypto policy

RHEL controls which cryptographic algorithms every compliant application may use through a
single system-wide setting called the *crypto-policy*. Show it:

[source,bash,role=execute]
----
update-crypto-policies --show
----

You should see `DEFAULT`. On RHEL 10.1+, the `DEFAULT` policy *already includes* the
post-quantum algorithms — there is nothing extra to enable.

[NOTE]
====
On the earliest RHEL 10.0 release, post-quantum algorithms were a Technology Preview that
required an extra package and a `DEFAULT:TEST-PQ` sub-policy. From RHEL 10.1 onward that step
is gone — PQC is in `DEFAULT`. This lab uses a 10.1+ image, so you simply see `DEFAULT`.
====

== Step 3 — See which key exchange algorithms OpenSSH supports

SSH negotiates a shared session key using a *key exchange (KEX)* algorithm. Ask OpenSSH which
ones it offers:

[source,bash,role=execute]
----
ssh -Q kex
----

Now filter that list for the post-quantum entry:

[source,bash,role=execute]
----
ssh -Q kex | grep mlkem
----

You should see:

[source,text]
----
mlkem768x25519-sha256
----

[IMPORTANT]
====
`mlkem768x25519-sha256` is a *hybrid* post-quantum key exchange. It combines the classic
X25519 elliptic-curve exchange with the post-quantum *ML-KEM-768* (FIPS 203). The shared
secret stays safe unless *both* are broken — so you get post-quantum protection today without
giving up the proven classical algorithm. This is the single most important defense against
"harvest now, decrypt later" for SSH.
====

== Step 4 — Confirm it is the preferred algorithm

Check the effective client configuration to see which KEX algorithms SSH will actually offer,
in order of preference:

[source,bash,role=execute]
----
ssh -G node1 | grep -i kexalgorithms
----

`mlkem768x25519-sha256` appears *first* in the list, which means SSH will try the
post-quantum exchange before any classical one.

[TIP]
====
Because this is governed by the system-wide crypto-policy, *every* crypto-policy-aware
application on the host — OpenSSH, OpenSSL, GnuTLS — picks up post-quantum support from the
same setting. You configure it once, and the whole system follows.
====

Your foundation is in place. In the next module you will open a real SSH connection and prove
that ML-KEM is actually used on the wire.
